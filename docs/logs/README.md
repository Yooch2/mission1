## 이번 실행 조건

- `mission1-proof-20261109t091318z-53830` 이름·라벨을 쓴 별도 자원으로 실행했다.
- 웹 포트는 기존 8080을 점유하지 않도록 Docker가 고른 `127.0.0.1:50223`을 사용했다.
- hello-world는 기존 태그의 digest를 지정해 pull했다. 이미 내려받은 이미지라
  `Image is up to date`가 출력됐으며 새 레이어를 다운로드한 실험은 아니다.
- 캐시 없는 빌드에서도 베이스 이미지 FROM은 CACHED로 표시될 수 있다.
  비교한 것은 두 COPY 단계로, 일반 빌드는 CACHED, --no-cache는 DONE이다.
- 현재 `site/index.html`은 v2 문구다. 이번 이미지도 해당 파일로 빌드했으므로
  응답의 v2 문구를 과거 v1 이미지 실험과 구분해야 한다.
- writer 삭제 후 reader가 같은 타임스탬프를 읽었다. `volume inspect`의
  Mountpoint와 읽기 전용 마운트의 디렉터리 목록도 같은 로그에 들어 있다.
- 실행 전후 기존 컨테이너·볼륨 ID와 hello-world/nginx/ubuntu 태그의 이미지 ID가
  유지됐음을 확인했다. 이번 실습 자원은 정리했으며 빌드 캐시는 삭제하지 않았다.

- 스크린샷 6개는 [../img/](../img/)에 있다. 파일별 설명은 루트 README의 디렉터리 구조 절을 참고한다.

  본문 내용을 복사해 원본 로그라고 표기하지 않았다.
- 과거 트러블슈팅의 원본 전체 로그는 별도로 보관돼 있지 않다.
